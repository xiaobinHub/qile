## 已确认代码问题

### C01 · P1 · 停止后续重复后，先前未完成安排消失

位置：`backend/lele_growth/business_operations.py:164`、`frontend/parent/src/domain/calendar.ts:123`，以及后端同文件 `sync_series()`。

复现：创建从 2026-10-01 开始的每日重复任务；在 10-05 选择“本次及以后”，关闭重复开关并保存。前后端都会根据最新的顶层 `recurrence=null` 直接按单次任务计算，跳过仍然存在的旧规则版本。

独立样例结果：10-01 至 10-04 的日历任务数量从 4 变为 0。后端请求 10-02 的任务发生返回 409“该日期没有此任务”。版本记录仍保留 2 份，但历史未完成安排已无法正常显示或完成；已有完成快照仍可显示。

建议：发生计算应依据按生效日期分段的规则版本，不能用最新顶层重复状态决定是否跳过所有版本。同步修复前后端；增加“重复→单次”“单次→重复”跨版本区间、历史完成撤销及未来再编辑的独立预期测试。

### C02 · P2 · 整个系列修改“每月日期”时丢弃输入

位置：`backend/lele_growth/business_operations.py:247`。

复现：现有每月 15 日任务，打开该次任务，将“每月日期”改为 20，日期字段保持原日期，范围选择“整个任务系列”。提交的 `monthDay=20` 被服务端改回旧规则的 15，操作仍返回成功。

原因：`scope=all` 分支在日期未变化时，无条件用旧 `series.recurrence.monthDay` 覆盖已通过验证的新规则字段。

建议：保留显式修改的 `monthDay`；仅在日期改变且月份规则未独立修改时执行必要的联动。分别验证只改日期、只改每月日期及同时修改的情况。

### C03 · P2 · 修改重复次数时仍沿用旧次数

位置：`backend/lele_growth/business_operations.py:256`。

复现：从 10-01 开始、总计 5 次的每日任务，在 10-03 把“重复次数”改为 10，选择“本次及以后”。服务端保存的次数为 3，用户提交的 10 被丢弃。

原因：只要新旧规则都是次数结束，就无条件执行“旧规则次数减去已发生次数”。即使用户显式修改次数，也执行同一计算。

建议：区分用户是否修改了次数；未修改时可保留原系列的剩余次数约定，修改时按明确的“总次数/本次起剩余次数”语义计算。无论采用哪种界面约定，都不能静默忽略新输入。

### C04 · P2 · 发布包包含未跟踪源码，却标记为干净提交

位置：`scripts/package_release.py:48`，结合 `release_files()` 对后端目录的递归扫描。

复现：在已提交的隔离副本新增一个未执行 `git add` 的后端 `.py` 文件。该文件进入归档及逐文件清单，但 `workingTreeDirty=false`，包名也没有 `dirty` 标记。

原因：状态检查使用 `--untracked-files=no`，收集源码却包含未跟踪文件。发布包与其标记的 Git 提交无法一一对应。

建议：对实际发布文件集合检查 Git 跟踪和状态，正式模式拒绝未跟踪或未提交内容；需要显式开发包时正确标记。对代码/资源的发布校验应同时包括新增、修改和删除。

### C05 · P2 · 入口资源缺失时仍可生成“干净”发布包

位置：`scripts/package_release.py:37`。

复现：在隔离副本删除家长端 HTML 所引用的入口 JS，并把该删除提交为新版本。脚本仍成功打包，包含 HTML，但没有其入口 JS，且 `workingTreeDirty=false`。使用该包会导致家长页面无法启动。

原因：只检查 `index.html` 是否存在，没有检查 HTML 引用资源和 JS 分块、CSS 字体等依赖是否齐全；逐文件哈希只能验证已收录文件。

建议：打包前核对两个入口的全部资源依赖，可使用 Vite 生成的构建 manifest，并验证动态分块及字体；对解压后的包执行页面/资源启动检查，缺失即拒绝打包。

当前工作区的静态文件与已验收版本一致；C05 是已验证的发布校验缺口，并不表示本地当前页面缺少 JS。

## 生产运维准备缺口

### O01 · P1 · 首次建库、升级及管理员引导尚无生产入口

位置：`backend/lele_growth/child_service.py:530`、`:565`，以及 `deploy/run.py`。

`initialize()`、`bootstrap()` 等运维入口明确拒绝 `environment=production`；生产运行入口不初始化或升级数据库。隔离的 production 配置调用两者均在连接数据库前返回 403。首次部署到空库或旧版库，现有交付不能完成 v4 结构及首个管理员的准备。

这些 development 防护符合既有约定，不应直接删除或把生产配置伪装成 development。上线前需要独立、显式、可审计、经过隔离演练的生产初始化/迁移与管理员引导方案，并包含版本核验及回退；已有生产库则需验证其确已完成相同准备。

### O02 · P2 · 暂存 OSS 对象的生产维护尚未打通

位置：`backend/lele_growth/media_migration.py:141`。

取消上传/编辑会留下暂存或失败对象，当前安全清理算法可保留历史引用并处理失败重试，但其入口拒绝 production；生产配置隔离复现返回 403。部署模板也未提供对应维护执行入口。长期运行后这些对象无法按现有流程清理。

建议：提供单独生产维护入口或受控作业，先支持只读预览，再以显式授权执行现有安全算法，并验证引用保护、并发上传、部分失败及重试。不要用全桶生命周期或未经元数据核对的直接删对象替代。
