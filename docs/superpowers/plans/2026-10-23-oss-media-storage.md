# 阿里云 OSS 文件存储接入实施方案

日期：2026-10-23。状态：用户已批准，已完成本地实施及存量图片迁移，验收记录另附。

## 1. 目标与范围

把礼品图片等持久化二进制文件放到 OSS，数据库保存文件元数据与关联关系。账号、孩子、任务、积分、礼品配置、权限和业务审计继续使用 PostgreSQL。

本轮首先接通已有礼品图片的上传、预览、替换、移除，以及备份导出与恢复。文件服务预留附件用途，后续新增文件类型时按用途明确允许格式和大小；不直接开放任意文件上传。

导出的 JSON、打印 PDF 继续提供下载，不自动改成云端备份产品。需要持久化的文件以后统一使用本轮文件服务。

先在本地开发环境 18787 / 18788 和隔离测试库实施。独立生产目录、8787 生产服务和阿里云应用发布不在本轮实施范围内，生产切换另行确认。

## 2. 已核实的现状

- `GiftEditor` 在浏览器中压缩图片，通过 `gift.save` 把 `imageData` Data URL 提交到后端。
- 原始选择文件限制 10MB，当前压缩后图片上限 180KiB；PNG、JPEG、WebP 为现有允许格式。
- 图片随礼品 JSON 写入 PostgreSQL，业务快照和导出也会携带这些内嵌图片。
- 本地开发库礼品表当前有 5 条记录，5 张图片均为内嵌数据，Base64 字符串合计 396,539 字节，约 387KiB。这不是生产数据库的统计。
- 当前数据库版本为 v3；孩子成员权限、逻辑删除、修订号、成员版本、操作 ID 和未知保存结果处理必须保留。
- 已在本地虚拟环境安装官方 `oss2==2.19.1` 用于后续验证；尚未修改业务代码、写入 OSS 配置或上传对象。

## 3. 存储与访问架构

使用 Bucket `xbproject`，深圳区域 `cn-shenzhen`。用户提供的 Bucket 地址为 `https://xbproject.oss-cn-shenzhen.aliyuncs.com`；SDK 使用区域 Endpoint `https://oss-cn-shenzhen.aliyuncs.com`。

上传路径：浏览器压缩和预览 → 应用后端校验与授权 → 后端上传 OSS → 数据库登记元数据 → 保存礼品与文件 ID 的关联。

读取路径：浏览器请求同源图片接口 → 后端验证登录和孩子访问权限 → 从 OSS 读取 → 返回图片字节。

第一版由后端中转上传和读取，不向浏览器下发 AccessKey，也不直接公开 OSS 对象地址。现有图片很小，该方式能保留权限控制，且不需要浏览器跨域配置。

不使用长期公开链接或长期签名链接作为图片字段，以免成员被移除或孩子被删除后，旧链接仍可绕过应用权限读取。

### 3.1 对象组织

示例：

```text
lele-growth/development/children/{childId}/images/{sha256}.webp
lele-growth/production/children/{childId}/images/{sha256}.webp
lele-growth/development/checks/{runId}/...
```

开发、生产及测试路径隔离。同一孩子相同内容可以复用对象，不做跨孩子去重，避免权限耦合。对象 Key 由服务端生成，不接受浏览器传入任意 Key。

对象按私有访问写入。先检查 Bucket 现状；如果这个 Bucket 还供其他项目使用，不擅自修改全桶 ACL、生命周期或 CORS，使用项目目录和对象级访问设置隔离。

### 3.2 密钥与权限

- 凭据保存在现有被 Git 忽略的服务端私有目录，文件权限设为 600；支持通过环境变量注入。
- 非敏感配置与凭据分离，提供无密钥的示例配置。
- 前端、构建产物、响应、审计、截图和日志均不包含密钥或签名请求头。
- 建议使用只允许项目目录的 RAM 凭据；正常业务只授予必要的上传、读取和对象 ACL 权限。清理工具的删除、列举权限独立限制在指定目录。
- 密钥已出现在对话中，建议在实施时替换为上述受限凭据，新的凭据通过本机私有配置提供。

## 4. 数据结构与接口

### 4.1 数据库

新增 `media_assets` 元数据表，包含：文件 ID、孩子 ID、上传者 ID、对象 Key、内容 SHA-256、MIME、字节数、上传请求 ID、状态、创建时间及关联时间。图片二进制和 Base64 不进入该表。

文件状态至少区分上传中、暂存、已关联和失败。上传请求 ID 对同一孩子和上传者唯一，同 ID 不同文件内容返回冲突；同一请求重试可查询或复用既有结果。

礼品增加可选 `imageAssetId`。读取接口生成只读的同源 `imageUrl`。迁移过渡期可读取旧 `imageData`；上传和完整性核验通过后，从礼品 JSON 中删除 `imageData` 键，仅保留文件 ID，不保留空字符串占位或重复 Base64。没有图片的礼品省略图片字段。

存量图片清理是本轮必做交付，不以仅支持新上传作为接入完成。完成后，普通业务写入、快照生成和旧备份恢复都必须在持久化前完成图片引用转换，阻止 Base64 再次进入数据库。

增加独立、可重复执行的 v3 → v4 数据库迁移，兼容全新初始化。结构升级不修改任务、积分、礼品状态和业务修订号；现有记录转移单独执行。

### 4.2 接口

| 接口 | 用途 | 保护 |
| --- | --- | --- |
| `POST /api/children/{childId}/assets` | 上传压缩后的图片，返回文件 ID 和预览地址 | 登录、来源、CSRF、孩子可写权限、成员版本、上传请求 ID |
| `GET /api/children/{childId}/assets/{assetId}` | 同源读取图片 | 登录、孩子访问权限、文件所属孩子和状态 |
| `GET /api/children/{childId}/assets/uploads/{uploadId}` | 查询上传是否完成 | 上传者身份和孩子权限，不泄露其他用户的结果 |
| 现有 `gift.save` | 关联文件 ID，保存礼品 | 继续使用业务修订号、成员版本和操作 ID |
| 现有导出／恢复接口 | 导出便携备份；恢复时重新建立文件关联 | 沿用当前导出、恢复权限；保持恢复的管理员限制 |

已关联图片按当前孩子权限读取；暂存图片只允许上传者预览。归档孩子可读不可上传或修改；已删除孩子、被移除成员、失效账号的新请求全部拒绝。另一个孩子的文件 ID 不可直接关联或读取。

图片响应使用正确 MIME、`nosniff` 和私有 `no-store` 缓存策略。后端只读取数据库登记的对象，不根据用户提供的 URL 抓取外部资源。

## 5. 上传、失败与并发处理

1. 浏览器沿用当前图片选择和压缩规则，先展示本地预览，再上传到应用后端。
2. 服务端检查实际大小、图片格式、文件头及可解码性；不只相信扩展名和浏览器 MIME。限制解码尺寸，不接受 SVG、HTML 等主动内容。
3. 短事务检查权限并登记上传意图，随后在数据库事务外执行 OSS 网络上传，避免长期占用孩子锁。
4. 上传结束后，重新检查账号、孩子状态和成员版本，登记暂存结果。上传期间被撤权或删除的孩子不能获得有效文件关联。
5. 点击保存礼品时，在现有孩子锁和业务事务中验证文件所属、状态及上传者，关联礼品并标记文件已关联。上传本身不消耗业务修订号。
6. 上传或保存失败保留表单输入。OSS 不可用时明确提示错误，不静默退回把新图片写入数据库。
7. 同一文件的上传重试沿用原上传请求 ID。结果不明确时先查询状态；礼品保存继续使用原业务操作 ID，不自动创建新编号盲目重试。
8. 切换孩子、退出登录或权限失效时中止上传、清除预览并隔离迟到响应，复用现有会话和孩子上下文保护。
9. 点取消后未使用的上传文件进入暂存清理范围，不影响现有礼品。

服务端校验在新上传入口收紧，但不通过重编码静默改变历史图片内容。浏览器的 10MB 原图选择和 180KiB 压缩上限暂时不变。

## 6. 备份与历史文件

### 6.1 导出

保持备份是可独立恢复的 JSON 文件。导出时把所引用的 OSS 图片读取后嵌入备份的 `imageData`，不导出临时图片地址、私有对象 Key 或凭据。临时生成的 Base64 仅用于导出响应，不写回数据库。

若有图片无法获取，导出明确失败并告知原因，不生成看似成功但缺图的备份。保留当前导出内容和访问权限范围。

### 6.2 恢复

兼容旧的 Base64 图片备份。先验证整个备份，再把其中图片上传到目标孩子的 OSS 目录，最后重新校验权限、成员版本和修订号，原子提交业务数据。任何一步失败都不提交半份业务数据。

恢复进度与错误在原页面展示；限制上传并发和总量，遵守现有备份大小限制。跨孩子恢复时生成目标孩子的文件引用，不复用来源孩子的私有文件权限。

### 6.3 清理

这里区分数据库内嵌图片清理与 OSS 对象清理：前者必须完成，后者需保留仍被历史记录引用的图片。

自动清理仅针对超过 24 小时、确认未被礼品或业务快照引用的暂存 OSS 对象。删除或替换礼品图片时，不立即物理删除旧对象，因为历史快照或恢复仍可能使用。

孩子逻辑删除只撤销文件读取与修改权限，不连带物理删除 OSS 对象。已关联对象的永久清理另做可预览的维护流程，不配置粗放的整目录过期删除。

## 7. 存量图片迁移

新上传链路验证通过后，提供独立迁移工具，默认仅 dry-run。清单包含候选记录数、图片大小、目标 Key、可复用对象及异常，不输出图片内容或凭据。

按用户补充要求，迁移范围包括当前礼品图片和数据库历史快照中的内嵌图片副本，并扫描历史业务记录、审计及迁移记录的相关 JSON 字段是否还存在实际图片内容。只处理确定的图片字段，不对任意字符串盲目替换，不删除历史业务记录。

已逻辑删除孩子保留的图片也按所属孩子迁移到私有 OSS，以清理数据库内嵌内容；保持孩子删除状态、成员权限和不可恢复规则，不重新开放访问。原始图片损坏或无法核验的记录留在异常清单，保留原数据并阻止报告“清理完成”。

前述 5 张统计仅覆盖当前本地礼品表。历史副本、不同版本图片和生产环境均须另外只读统计，迁移清单需覆盖这些记录。

正式迁移步骤：

1. 保存迁移前的受保护备份、业务修订号、记录摘要和图片哈希。需要保留图片内容的原始回滚备份放在数据库外的受限位置，不在数据库另存一份 Base64 作为备份。
2. 按孩子分批上传；核对上传字节数和完整性校验。
3. 在孩子锁内重新确认图片未被其他操作修改，再关联文件 ID 并删除该条 `imageData`。历史快照中的图片也替换为对应引用，保留当时实际图片版本，不用当前礼品图片覆盖历史图片。业务修订号、历史时间和非图片业务内容不变，单独记录迁移审计。
4. 历史快照的存储 JSON 表示发生变化后，重新计算对应 `content_sha256`；迁移清单保存原摘要和新摘要，以便核对。幂等请求指纹等原有请求校验值不改写。
5. 失败的记录保留原 Base64，成功的记录可正常读取，工具支持重复执行和断点继续；异常修复前不把迁移标记为完成。
6. 全量比对迁移清单、图片内容哈希及关联关系，检查其他业务记录未变；再次扫描数据库相关图片字段，要求内嵌图片数量与字节数均为 0。

该迁移作为独立工具分批执行，但属于本轮接入的必做阶段。用户审阅完整方案后再实施，不在方案审阅期间直接清空字段。

数据库逻辑字段清理完成后，旧行版本和 TOAST 空间通过 PostgreSQL 正常维护回收复用，数据库文件不一定立即缩小。不为追求立即缩容擅自执行锁表重写；物理备份和 WAL 的保留遵守既有数据库维护策略。

## 9. 验收标准

全部写入测试只使用独立 `lele_test*` 数据库和专用 OSS 测试目录，记录创建的 Key；清理严格限定为本轮测试对象，不列举或删除其他项目对象。

- 新礼品、新图片、替换、移除、取消、兑换和撤销兑换正常；数据库不保存新图片 Base64。
- OSS 对象实际存在、内容哈希一致，匿名直接读取失败；应用内有效成员可读取。
- 未登录、其他孩子、无权限用户、撤权账号、删除孩子及归档写入均得到正确拒绝。
- 上传失败、网络中断、重复提交、上传成功响应丢失、保存冲突和迟到响应不造成重复关联或跨孩子显示。
- 旧图片正常显示；旧备份及新备份可独立恢复；OSS 图片不可用时导出不伪报成功。
- 迁移 dry-run、重复执行、并发编辑检测和兼容版本回滚通过，任务、积分、账号和业务修订号不变；历史快照的图片内容可核验，存储摘要与修改后的 JSON 一致。
- 当前礼品、历史快照及其他相关 JSON 字段中实际内嵌图片的数量与字节数为 0；普通保存和旧备份恢复均不重新入库 Base64。
- 上传过程中不长时间持有业务锁；文件大小、格式、解码尺寸和错误脱敏验证通过。
- 两端类型检查、构建、相关后端用例和浏览器回归通过，密钥扫描及私有文件 URL 隔离检查通过。
- 本地开发环境实测通过后再安排生产发布；不以 SDK 安装或单次上传成功代替整条业务验收。

## 10. 回滚与交付

保留改造前代码、私有配置备份与迁移清单。结构升级采用新增表与兼容字段；旧图片格式仅在过渡读取和备份输入阶段兼容，清理完成后不作为正常数据库存储格式。

已经使用 OSS 文件引用后，不能直接关闭 OSS 或退回完全不认识文件引用的旧版。日常回滚使用仍支持文件引用的兼容应用版本，保留 OSS、元数据表和图片关联，不把 Base64 回填进数据库。数据库外原始备份保留为受保护的灾难恢复材料，整库恢复另行确认。

交付物：接入代码、无密钥配置示例、RAM 权限建议、v4 升级脚本、存量 dry-run／迁移／残留核验工具、兼容回滚方案、回归记录和本地启用说明。任何清理、迁移或测试日志均不包含密钥和签名 URL。
