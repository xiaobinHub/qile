# 云服务器发布前目录整理

目标：将当前应用源码、测试、部署文件与旧版工具分开；仅重构路径，不改变 API、数据库结构、权限、页面行为及业务数据。基线为 `e3ed8a9`，本轮不发布服务器。

## 目录决策

- `backend/lele_growth/`：可安装的 Python 应用包，包含现有服务、存储、媒体及领域逻辑；SQL 作为包内 `db/` 资源。
- `frontend/parent/`、`frontend/admin/`、`frontend/shared/`：两个 Vite 应用和共享 shadcn/ui 源码，继续使用根目录同一份 npm 锁文件。
- `tests/backend/`、`tests/browser/`、`tests/domain/`、`tests/fixtures/`：测试及只读样例，不包含真实业务数据。
- `scripts/dev.py`：本地生命周期工具；根 `dev.py` 仅保留旧命令兼容入口。根目录两个本地测试快捷方式继续可用。
- `deploy/`：Linux 运行入口、systemd、Nginx 及不含密钥的示例。
- `legacy/`：旧版 HTTP 服务、单文件页面和 RDS 迁移，仅供历史对照及受限回归；按用户补充要求删除本地生产命令、应用及控制脚本。
- `web/`：已验证构建产物；`docs/`：说明、设计和验收资料；`data/`：被忽略的私有本地配置及数据库，位置不变。

## 取舍

只移动文件而继续使用顶层隐式导入，会留下部署路径依赖；本次同时规范为 `lele_growth.*` 包导入。不引入新的前端工作区管理工具，也不按此次目录整理拆解大业务模块。旧生产目录及其进程、数据库、锁定发布内容均不改动。无关的 `docs/美森API接入要求.md` 保留原位且不纳入版本。

## 验证与回退

所有写入测试使用 `lele_test*` 数据库及 18887/18888 临时端口。目录移动前后的数据库摘要覆盖每张表，测试后检查开发账号、孩子及业务记录的内容与修订号一致。仅因已有会话正常过期而产生的变化需单独说明。

Git 基线可恢复旧代码结构；不回滚或改写开发业务数据。运行中进程在移动前停止、验证后以新模块名启动，避免旧代码与新目录混用。Python 发行包包含 SQL；服务器发布文件不包含旧版程序、测试输出、开发数据库、密钥或 macOS 工具。

用户补充要求：本地仅保留开发测试环境，当前仓库本地生产启动/停止命令、应用和控制器均删除；独立旧生产目录与进程不自动删除或停止。
