# 积分商城设计说明

## 目标

在现有“积分流水”右侧增加“积分商城”，让家长创建一次性礼品，乐乐使用已有积分兑换。兑换、撤销均通过不可变积分流水记录，确保余额可追溯。

## 交互设计

- 导航顺序为“日历 / 积分流水 / 积分商城 / 设置”。
- 商城展示当前积分、可兑换礼品和已兑换礼品，并在页面右上提供“管理礼品”。
- 每条礼品是一个一次性实例；相同礼品需要多次兑换时，可创建多条同名礼品。
- 点击可兑换礼品后弹出确认框，显示当前余额、所需积分和兑换后余额。积分不足时禁止确认。
- 兑换成功后礼品移入已兑换区；撤销兑换会追加返还积分流水，并让礼品重新回到可兑换区。
- 管理弹窗支持创建、编辑和删除未兑换礼品。已兑换礼品需先撤销才能再次编辑。

## 数据设计

- `AppData.schemaVersion` 从 1 升至 2，新增 `gifts` 数组；旧数据自动补充空数组后迁移。
- `Gift` 保存标识、名称、积分、压缩图片、状态、兑换流水标识和创建/修改/兑换时间。
- 流水新增 `gift-redeem` 和 `gift-reversal`。兑换流水保存礼品名称及积分快照，不重复保存图片。
- 礼品图片在浏览器中缩至最长边 640px，优先编码为 WebP，逐步降低质量/尺寸至 180KB 以内，再以 Data URL 写入 JSON。
- 商城写入继续使用完整 AppData、revision 冲突检测、原子落盘和自动备份。

## 规则与失败处理

- 礼品名称必填、最多 40 字；积分必须为 1–99999 的整数；允许同名礼品。
- 兑换前重新检查礼品状态和余额，保存期间禁用按钮，避免重复提交。
- 两个浏览器同时兑换时，第一笔成功，第二笔因 revision 冲突回滚并提示刷新。
- 兑换和撤销必须在一次 AppData 保存中同时更新礼品状态与流水；失败时整体回滚。
- 已有任务、完成快照、手动积分与备份格式保持兼容。

## 验收

- 旧数据可无损加载并在首次保存后升级。
- 创建、编辑、删除、兑换、积分不足、撤销和浏览器冲突均有明确结果。
- 图片随刷新、重启、导出和导入保留。
- 积分流水可筛选礼品来源并正确计算变动后余额。
