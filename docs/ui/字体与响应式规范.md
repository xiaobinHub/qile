# 字体与响应式规范

适用：当前 React 家长端、管理端及共享组件。单位为默认根字号 16px 时的 CSS 像素；实际使用 rem，保留浏览器字体偏好。2026-10-22 建立。

## 文字层级

| 角色 | 字号 / 行高 | 字重 | 使用位置 |
| --- | --- | --- | --- |
| `page` | 22 / 30 | 600 | 页面主标题、日历日期、品牌名称 |
| `detail` | 20 / 28 | 600 | 弹窗、抽屉、设置详情标题 |
| `section` | 16 / 24 | 600 | 区块标题、表单分组 |
| `card` | 15 / 22 | 600 | 礼品、内容卡片名称 |
| `body` | 14 / 22 | 400–500 | 正文、导航、菜单、按钮、标签、输入、表格正文 |
| `caption` | 13 / 20 | 400–500 | 帮助说明、时间、表头、分组名称、次要信息 |
| `meta` | 12 / 18 | 400–500 | 日历紧凑预览、徽标、数字单位 |
| `number` | 24 / 32 | 600 | 积分与统计数值 |

同一语义在 PC 和 iPad 上使用同一层级。错误和操作反馈使用 body，不能降为 meta。普通说明使用 caption；不得通过低对比度、小字号隐藏重要说明。默认字体沿用 Inter / 苹方 / 系统中文回退组合。

### 特定用途与例外

- 触控设备的输入框和文本域使用 section，即 16 / 24；文字标签仍为 body。控件至少 44px 高。
- 日历任务预览保留已有的宽屏 body、窄屏 meta 规则，不把所有任务强行压小。短时长周事件最小文字为 meta；时长和事件定位仍由业务日历决定。
- 孩子卡牌头像保留装饰字号：肖像文字 4.375rem；设置大头像保留 3rem / 2.25rem / 2rem，邀请卡头像为 1.1875rem。它们不是标题或正文，不用于普通文字。
- 礼品积分单位和状态徽标为 meta；礼品名称使用 card，最多显示两行，并保留完整名称的 title。
- 打印使用独立 pt 和动态纸张密度参数。本次不改变打印规则、分页或 PDF 生成逻辑。

## 代码使用

字体唯一数值源位于 `shared-ui/src/typography.css`。Tailwind 使用 `text-page`、`text-detail`、`text-section`、`text-card`、`text-body`、`text-caption`、`text-meta`、`text-number`；CSS 使用 `font-size: var(--text-body)` 和 `line-height: var(--text-body--line-height)`。

现有 shadcn 的 text-sm / text-xs / text-base / text-xl / text-2xl 分别映射 body / meta / section / detail / number。text-lg 也归并到 section。共享 `cn` 已注册语义字号，使页面覆盖字号时能正确合并，且不把字号误认为文字颜色。

- 禁止新增页面专属的任意字号和按 vw 缩放的正文、导航或菜单文字。
- 修改字号时同时选用对应行高，避免继承旧的过大行高或裁字。
- 字重使用 400、500、600；数字使用 `tabular-nums`。标题保持真实的 HTML 标题层级，视觉大小不替代语义结构。
- 标题、导航及正文默认不随断点缩小；优先换行、调整列数、收敛间距。
- 调整共享组件后同时验证两个入口，不用全局 `!important` 强制覆盖所有文字。

## 页面密度

| 区域 | 规则 |
| --- | --- |
| 页头 | 常规单行 72px；图标 40px、头像 36px；PC 左右 24px，iPad 左右 16px |
| 日历工具栏 | 单行最小 64px；按钮 PC 36px，触控 44px；组内 8px、组间 16px |
| 商城 | ≥1024px 四列、768–1023px 三列、<768px 两列；卡片内边距 12px、列间距 16px，窄屏间距 12px |
| 礼品卡片 | 图片 5:3，信息区间距 8px，名称预留两行，操作底部对齐 |
| 设置 | ≥1200px 左栏 208px，768–1199px 左栏 184px，<768px 单列；右侧内边距 24 / 20 / 16px |

768–1023px 的日历工具栏采用两行：第一行日期与日期切换；第二行月/周、打印及新建。页头隐藏副标题。小于 768px 保留双行页头和窄屏设置导航。触控区域与字体大小分开设置，主要操作至少 44×44px。

## 走查与维护

静态盘点见 [源码走查清单](typography-20261022/source-audit.json)，包含原选择器、断点、原字号、目标角色；这是源码声明记录，不等同于浏览器最终计算字号。

另有 [组件字号类盘点](typography-20261022/component-audit.json)，列出两端及共用 TSX 组件原有和调整后的字号类，涵盖登录、资料、用户表格、表单及各类浮层。

新增代码使用 `npm run check:typography` 检查，防止重新引入 px / vw 屏幕字号和 JSX 任意像素字号。该检查不覆盖旧版入口、打印 pt 或头像装饰 rem；语义角色是否正确仍需页面走查。

运行 `npm run test:browser`，使用专用 `lele_test_unified_ui` 测试库和 18887 / 18888 临时端口。扩展的字体验收覆盖 PC 1280×800、1440×900，iPad 768×1024、820×1180、1024×768、1180×820 和 390px 窄屏。视觉样例由浏览器拦截 GET 响应注入，拒绝写入；不会存入开发或正式业务数据。

只复核字体和布局时运行 `npm run test:browser -- --typography-only`，同样使用隔离测试库，专项结果独立保存在 `output/playwright/typography-focused/`，不会覆盖完整业务回归报告。

验收产物位于 `output/playwright/shadcn-unified/typography/`：各页面截图及 `computed-type-audit.json`。PC 和 iPad 竖屏遍历所有设置子页；同时检查导航、商城、任务弹窗、管理端表格和创建账号弹窗。原有回归继续验证账号、任务、积分、备份、焦点、权限和打印。

旧版根目录 `index.html` 属于独立旧入口与版本对照，本轮记录其存在、不迁移其样式；当前开发路由使用 React 构建产物。独立生产目录不随本次代码和构建更新。

浏览器模拟不能代替真实 iPad / Safari、软键盘和系统打印验收。文本放大测试与实际浏览器 200% 缩放分别记录，不能相互冒充。
