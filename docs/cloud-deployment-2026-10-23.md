## 现场发现

服务器为 Rocky 系列，系统 Python 3.9 不满足项目 Python 3.13 要求，需独立安装运行环境。现有 8787/8788 端口空闲。RDS SSLRequest 返回 N；用户明确授权本轮跳过该问题，部署记录保留此边界，不声称 RDS 链路已加密。域名在本机受到代理 DNS 影响，DNS 与最终 HTTPS 还需服务器侧和真实外部客户端交叉核验。


## 域名现场阻碍

公网直接请求 `http://chenqile.cn/.well-known/acme-challenge/lele-probe` 返回 `403`、`Server: Beaver`，正文明确为 `Non-compliance ICP Filing` 并跳转阿里云备案拦截页；服务器本机同路径返回 200。这是已验证的备案/接入备案拦截，不能把本机 200 当作域名已上线。Let’s Encrypt 两次验证均被此拦截阻止，现有 OSS 凭据调用 AliDNS 返回 Forbidden.RAM。未绕过备案、未使用不受信任证书对外冒充 HTTPS。内部部署和迁移核验继续，公开切换等待用户提供可用域名或完成备案。

## 备案完成后的正式切换

1. 在真实外部网络确认两个域名的 ACME 文件不再被备案检查拦截；服务器自身返回 200 不足以确认。
2. 使用已有 webroot 重新申请包含 `chenqile.cn` 与 `admin.chenqile.cn` 的可信证书，确认 SAN、有效期和外部链验证。当前没有证书，不能直接加载 ready 配置。
3. 短暂冻结旧生产写入，重新读取旧库当前记录与完整快照。本次内部迁移是修订 317 的首轮核验，**不保证仍是届时最新数据**。
4. 若来源摘要未变化，可复核当前目标；若来源已变化，先保全当前内部预演库，再创建新的独立空目标并重新迁移，不能用整包覆盖现有孩子。源库保持不变，工具会拒绝非空目标覆盖。
5. 完成内容、图片、修订和权限核验，再备份项目当前 Nginx 配置，将 ready 文件部署为本项目配置，`nginx -t` 成功后重载。只修改本项目域名，不修改其他站点。
6. 从外部验证两个 HTTPS 页面、登录改密、只读业务页面、私有文件隔离及旧站点；确认后才将云端作为唯一日常写入入口，旧生产停止日常写入并保留回退资料。

## 回退边界

当前尚未切换，旧入口继续可用；如需撤销内部部署，停止本项目两个服务并保留新库/OSS/备份即可，原库无需回滚。不得删除原库、原目录或历史 OSS 对象。

一旦正式云端开始接受新的业务写入，回退不能直接恢复旧库写入，否则会形成数据分叉和丢失云端增量；应先保护新数据，再按兼容版本或单独迁移方案处理。数据库备份和旧源副本不能直接整包覆盖现用业务库。

RDS SSL 依用户明确要求暂缓，连接仍为 `sslmode=disable` 且明确允许未加密；没有将 SSH 传输加密或网站未来 HTTPS 误称为 RDS 链路已加密。后续需要单独启用并验证 RDS TLS。
